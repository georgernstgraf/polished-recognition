# Pitfalls — Audio Pipeline

Moved out of `PITFALLS.md` in #206; entries are verbatim. New pitfalls in this area are appended here.

- **`flush()` darf den Spool nicht truncaten, solange der Fragment-Worker ihn liest (2026-11-24, #198).** Die alte Reihenfolge (truncaten, dann Worker verwerfen) ließ einen Read über das Ende laufen: `IllegalArgumentException: PCM range [x, y) beyond buffer (0B)` aus `AudioRecorder.copyPcmRange`, aus dem `FragmentPreparer`-Worker, unbehandelt → Crash-Handler → Prozess weg mitten in der Aufnahme. Der Worker wird jetzt zuerst gestoppt und gejoint; zusätzlich loggt der Worker-Loop einen werfenden Read und lebt weiter, und ein Capture-Fehler parkt die Aufnahme PAUSED statt zu crashen.
- **`cacheDir/fragments/<sessionId>/` is a CACHE, not durability (2026-11-20, #182).** The live preparer commits every fragment there, and it is tempting to read "the audio is on disk" as a recovery path — it is not: the OS may clear `cacheDir` at any time, the dir does not survive an uninstall, and the #142 `session.json` exists only while the retention slider is non-zero (release default 0). Any recovery/replay feature must read `filesDir/journal/<sessionId>/` (#182), which keeps the COMPOSED upload from before the first attempt. Two consequences: the journal must never be gated by a setting, and it must never live inside the preparer's dir — `startFragmentPreparation` prunes that working set to one session, so sharing it would let a prune delete an unfinished dictation.

- **`session.json`'s `endedAt` is the SESSION END, not the stop tap (2026-11-12).** It is written by `recordSessionOutcome()` right next to `result.deliveredAt`, i.e. AFTER the pipeline finished — so "stop → raw text" computed against it comes out NEGATIVE, and "stop → delivered" comes out 0.00 for every session. Reconstruct the tap instead: `tap ≈ startedAt + lastFragment.endMs` (exact while the recording ran without pauses; pauses push it later). Sanity gate: `(lastFragment.sttSentAt − tap)` is the local encode time, so `0..10 s` is plausible and anything outside is a pause, a process restore, or clock skew. The gap between the pre-roll byte count and `bytes` in `prepare.json` is 32 000 B/s, which is also how the audio length is derived there.

- **`search = max(2 s, S)` + "cut in the late half" makes fragments 1.5–2× the nominal size (#124, fixed 2026-11-12).** The nominal boundary sat at `start + S` and the measured span was `[S + W/2, S + W]` with `W = S`, so a "10-s fragment" was really 15–20 s and a "21-s fragment" 31–42 s. Two knock-on bugs: the auto-sizer fitted `t(S)` on REAL upload durations but derived a NOMINAL size, so it undershot by ~1.75× and sat permanently on the 10-s floor; and the first live fragment only committed at 2S (20 s), so 61 % of all dictations never got a live fragment at all. The replacement geometry (slice + search window %) is defined in DOMAIN.md; when reading OLD code or logs, remember that a pre-#124 `fragmentSeconds` value must be doubled to compare.

- **#126 fixture construction: constant-byte frames are DC — the measurement's 80-Hz high-pass deletes them.** The old `SilenceCutterTest`'s `frame(level)`/`dip(size, level)` helpers (every byte = same value ⇒ every sample = 257·level ⇒ pure DC) read as FLOOR after `PcmConditioner.highPassOnly` — a "loud" dip becomes silence. Synthetic speech/levels for the metric must be zero-mean: **Nyquist squares** (sample k alternates +amp/−amp) pass the one-pole at ~0.985·amp with every full frame carrying the identical RMS. Related trap: the one-pole's start transient (fresh span ⇒ filter state (0,0), ~125-sample settling) makes the FIRST frame of a uniform span slightly LOUDER than frame 1 (overshoot) — forced cuts on uniform spans land at `spanStart + 480`, not `+ 160`.
- **`WavPcm` is lenient; the app's `WavReader` is deliberately strict (#122).** `WavReader` assumes the recorder's canonical 44-byte header and rejects ffmpeg output (which inserts a `LIST`/`bext` chunk before `data`, → `Missing data chunk`). The corpus material (and the `:analyzer` pipeline) uses `WavPcm.extract` (chunk walk). Do NOT loosen `WavReader` — it is a fail-fast guard for the recorder path.
- **MIXED-FORMAT bundles are real — session.json's `compressAudio` snapshot is NOT format truth (#149, verified in code).** Two designed mechanisms mix WAV and OGG within one bundle's `uploads/`: (a) the OGG→WAV transcoder-fallback rebuild (`FragmentPreparer.encodeFragment`'s catch block) re-encodes the prefix WITHOUT re-committing → fragments 0..N−1 keep their already-retained `upload_*.ogg` evidence while N onward are retained as `.wav`; (b) process-death recovery across a settings flip — `recover()` restores the manifest's format, init forces `fallbackToWav = wavMode`, so a session that died in OGG mode and resumes after compressAudio was flipped continues in WAV over an OGG prefix. Settings flips BETWEEN sessions never mix (`wavMode` is a session property). Consequence: any bundle consumer (e.g. `analyzer reconstruct`) must detect the format PER FRAGMENT from `uploadFile`'s extension and treat `provider.compressAudio` as advisory only.
- **A bare-fragment upload carries NO pre-roll even when `preRollMs` is recorded (#149).** `composeUpload`'s degradation path (pre-roll file missing, composition failure) returns the bare fragment — retained evidence keeps the FRAGMENT's name (`frag_%06d.<ext>`) while `session.json` still records `preRollMs` from the (existing) pre-roll side file. Cutting `preRollMs` off a `frag_*` upload would eat 1 s of real fragment audio. The pre-roll head is only present in composed `upload_%06d.<ext>` files — key any head-cut on the upload's NAME.
- **Bundle boundary precision is ±3 ms, not byte-exact (#149).** `startMs`/`endMs` are PCM-bytes/32 integer-divided (±1 ms truncation per edge) and `preRollMs` is `AudioDuration.estimateMs` ms-truncated (±1 ms). A FAITHFUL bundle can deviate up to ~3 ms per piece; a piece-duration check against `(endMs − startMs) × 32` bytes needs a ±3 ms (96-byte) tolerance — anything tighter false-discards good bundles, anything looser hides real damage.

- **Silently-swallowed diagnostics cost a debugging round (#117).** The shadow comparison's `catch (_: Throwable)` hid the crash for two on-device rounds (shadow removed in #143; the record remains as the canonical example). Rule: every failure path writes its own evidence record (error/exception/message/stack), plus a gate breadcrumb so "feature did nothing" is distinguishable from "feature failed".
- **The echo trim must run BEFORE the transcript is stored (#117 round 2).** `transcripts[i]` feeds fragment i+1's prompt AND its known tail — storing the untrimmed (echo-laden) text re-conditions the decoder on the duplicated words and compounds per seam.
- **Background audio defeats silence-aligned cuts — expected, not a bug (#117 round 2, verified under TV audio 2026-10-09).** With a movie playing, the RMS never drops below the silence threshold in the search window, so `SilenceCutter` finds nothing and the encoder falls back to the hard cut at the nominal boundary (3 of 4 fragments did). The graceful fallback is the designed behavior; seam quality was UNAFFECTED (0 dropped words under noise). Don't "fix" this by loosening the threshold — a lower threshold would risk cutting into quiet speech.
- **`FragmentPreparer.writePreRoll` must stay OUTSIDE the fragment encode's catch block (#117 round 2).** The fragment OGG transcode failure sets the session-level WAV fallback; a pre-roll transcode failure must only yield `null` (graceful degradation). Same for the WAV branch: its pre-roll write failure also degrades to `null`.
- **Pre-roll files are NOT manifest entries (#117 round 2).** Every operation that sweeps the session dir must account for them by name derivation (`frag_` → `preroll_`): `recover()`'s orphan keep-set includes them, the WAV-fallback rebuild re-creates them (its delete sweep wipes them), `prune()` deletes everything anyway. And they are written BEFORE `writeManifest()`/`notifyCommitted` — a committed fragment must never advertise a pre-roll it does not have.


- **An injected "keep forever" evidence-retention horizon must stay overflow-safe — `Long.MAX_VALUE / 2` deletes EVERY session dir on the first write (#146, hit 2026-10-15).** `AudioEvidenceStore.evict()` computes the age bound as `retentionSeconds() * 1000L`; the app wires real slider values (≤ 1.6e9 s), but the :analyzer CLI initially injected `{ Long.MAX_VALUE / 2 }` → `4.6e18 * 1000` overflows to a NEGATIVE bound → `nowMs - at > negative` is true for every parseable-time dir (name prefix OR mtime fallback) → the store silently `deleteRecursively()`ed the just-written evidence dir, and the analyzer run failed with a confusing `FileNotFoundException` on the NEXT file in the same dir. Use `Long.MAX_VALUE / 2000` (≈ 4.6e15 s, overflow-free) or a sane finite horizon. Symptom signature: files written moments ago vanish, the dir exists during writes but is gone one step later.
- The `AudioRecord` thread must run at `THREAD_PRIORITY_URGENT_AUDIO` to avoid buffer underruns on slower devices.
- WAV header requires little-endian byte ordering. Standard `DataOutputStream.writeInt()` is big-endian and will produce corrupt WAV files.
- **FFmpegKit is dead — do not add `com.arthenica:ffmpeg-kit-*`.** Retired 2025-01-06; ALL prebuilt binaries removed from Maven Central/CocoaPods/npm on 2025-04-01 (dependency resolution 404s). Community forks (`ffmpegkit-maintained` group-ID swap, `com.mrljdx:ffmpeg-kit-full`) are unmaintained and ship prebuilt `.so` blobs (10–40 MB APK, F-Droid reproducibility friction). For audio encoding use the platform `MediaCodec` + `MediaMuxer` instead (#60).
- **Platform Opus encode constraints (#60):** the `MediaCodec` Opus encoder is API 29+, `MediaMuxer.OutputFormat.MUXER_OUTPUT_OGG` is API 30 — both only safe because minSdk is 30. Encoder must be looked up via `MediaCodecList(REGULAR_CODECS).findEncoderForFormat(...)` (may be absent → throw and fall back to WAV); set input `presentationTimeUs` when queueing input buffers (MediaCodec propagates input PTS to outputs — computing PTS from output buffer sizes is impossible for compressed codecs); skip `BUFFER_FLAG_CODEC_CONFIG` buffers when writing to the muxer and only `muxer.stop()`/`start()` in the right order — `release()` alone is safe if never started.
- **PcmConditioner high-pass has an 80 Hz cutoff** — when writing tests, a sine with `periods` cycles over `count` samples is `periods/count * sampleRate` Hz; a "10 periods over 8000 samples" tone is 20 Hz and gets crushed by the filter (test bug that looks like an encoder bug).
- **WAV files can NEVER be byte-concatenated — rebuild one canonical header instead (#119, 2026-10-10).** Every WAV carries its own 44-byte header whose `data`-chunk size makes a conforming decoder stop at the first file, so a `copyTo` concat silently drops everything after it. This hit BOTH combiners for `compress_audio` OFF sessions: the acoustic pre-roll upload (`FragmentTranscriber.composeUpload`) decoded as the 1-s pre-roll only (gregor reported `duration: 1.0` for a 4.5-s upload; ~6/7 of a 112-s dictation lost, the delivered text a time-shifted sampling of earlier seam seconds), and the stop-time assembly (`FragmentPreparer.assembleChunks`) truncated any full-pass consumer to one fragment (the #117 shadow's `fullChars` 113 vs `fragmentChars` 315 — shadow removed since #143). OGG is the opposite — page chaining (RFC 3533) is a native format feature, so a byte-concat is a valid stream. Rule: any code that combines audio files MUST branch on format; WAV goes through `audio/WavAssembler.concat` (reads each source's PCM via `WavReader`, writes ONE `WavWriter` header). Corollary: the app's own `AudioDuration` parses the same header, so a corrupt composed WAV recorded `durationMs = 1000` for EVERY fragment — which silently poisoned the #116 latency profile and drove the auto-sizer to ~7-s fragments (guarded by a `STT_PROFILES_VERSION` bump that discards pre-fix samples).

- **A wrong-format upload is invisible to the unit tests that assert byte-equality (#119).** The #117 pre-roll test pinned the *broken* contract — `assertThat(uploaded).isEqualTo(preRoll + fragment bytes)` — so it passed while the device dropped 6/7 of every dictation. When a test asserts an exact byte layout of a produced media file, back it with a PARSE (canonical header → payload size/duration) so a format-invalid concat fails loudly. The fixed tests now read the composed upload via `WavReader` and assert the summed PCM size.
- **Snapshot/restore paths must catch `Throwable`, not `Exception`** — copying a large PCM buffer can throw `OutOfMemoryError` (an `Error`), which would otherwise kill the IME from inside `snapshot()`/`restore()`; persistence is best-effort and must never break the live session. Same for the lifecycle trace I/O. (#83.)
- **Chunking must happen at PCM level BEFORE Opus compression (#115).** An Ogg/Opus file cannot be split without a full decode+re-encode (MediaMuxer has no OGG sample-copy path); `WavChunker` splits the raw recording WAV instead, and each chunk is transcoded individually — never re-encode after compression "to split". Split boundary consequences: (a) the per-chunk WAV feeds `OpusOggTranscoder` through `WavReader`'s fail-fast parser, so chunk data must stay a valid 44-byte-header mono 16-bit WAV (`WavWriter.write`); (b) `PcmConditioner` runs per chunk (per high-pass state reset at each chunk edge — negligible for speech, accept it); (c) the 60 s segment floor (`MIN_SEGMENT_SECONDS`) can otherwise violate a small byte budget — `WavChunker` caps the floor at the size-derived budget (`min(segment, sizeBased)`), a deliberate deviation from the core.py original.
- **A `run` re-attempt into an existing run dir silently produces an EMPTY join (#129, 2026-11-12).** `FragmentPreparer.recover()` resumes from the `session/manifest.json` in the run's session dir: after a FAILED attempt (e.g. the 400 on a wrong STT model name) the manifest already covers the whole PCM, so the re-run offers **zero** fragments to the transcriber — `join=0`, `ratio=0.0`, and the run still reports `success`. `result.json` is the resume marker, so a session dir without one is stale by definition: `RunCommand` now wipes it first AND fails loudly when a run commits no fragments (a corpus WAV always yields at least the tail fragment). Related: the whisper.kik endpoint (gregor's official entry point) rejects the model id `large-v3` with HTTP 400 — it wants **`whisper-large-v3`** (`--model whisper-large-v3`), unlike gregor's own LAN endpoint.
