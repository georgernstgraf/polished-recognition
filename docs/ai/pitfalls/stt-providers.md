# Pitfalls — STT, LLM and Providers

Moved out of `PITFALLS.md` in #206; entries are verbatim. New pitfalls in this area are appended here.

- **Der Provider-Fehler-BODY ist das Signal, die Rate-Limit-Header sind es NICHT (2026-11-22, #75).** Das School-Gateway (nginx + LiteLLM) darf `x-ratelimit-*` und `retry-after` strippen oder ersetzen — in den 100 gemessenen Request-Records waren sie nie die Grundlage einer Entscheidung, der Body war immer da. Deshalb entscheidet `ProviderError` (aus dem Body) über `SttFailure.BUDGET`, und `headers`/`rateLimit` sind reine Diagnose. Wer eine Nutzer-Entscheidung an einen Header hängt, baut ein Feature, das auf genau der Installation verschwindet, für die es gedacht war. Zweiter Teil derselben Falle: `response.errorBody()` ist EINMALIG lesbar — einmal lesen, das Ergebnis auf der Exception tragen; ein zweiter Lesezugriff (z. B. im Transcriber) sieht nichts mehr. Und: die Feld-Kappung in `ProviderError` (64 Zeichen für `type`/`code`) darf NICHT auf `message` angewendet werden — sie kappte den Provider-Satz mitten im Satz (`… Spend=5.0006,` / Test `the measured budget body parses and is a budget refusal` hat es gefangen).

- **Ein `2xx` ist kein Erfolg: `SttResponse.text` ist zur Laufzeit `null`, obwohl Kotlin `String` sagt (2026-11-20, #183).** Gson füllt fehlende Referenzfelder nicht — `{"error":"bad gateway"}` mit Status 200 ergibt ein `SttResponse` mit `text == null`; Retrofit validiert nichts. Wer `.text` ungeprüft benutzt (etwa in `trimEcho`), bekommt eine NPE, die im `catch (Throwable)` des Workers als generischer Fehler landet — also unklassifiziert und ohne Journal-Grund. Regel: 2xx nur als Erfolg werten, wenn `text != null` (`hasTranscript`; die SENSELESS_COMPARISON-Warnung ist hier korrekt unterdrückt). **Leer ist NICHT fehlend:** `text == ""` ist die legitime Antwort auf ein stilles Fragment — `isBlank()` als Fehlerkriterium würde echte Diktate brechen.
- **`401`/`403` sind seit #183 kein neutraler „permanenter Fehler" mehr — Tests brauchen 410 (2026-11-20).** AUTH setzt das Session-Latch im `FragmentTranscriber`: alle späteren Fragmente werden ohne Request als Fehler verbucht. Ein Test, der „ein Fragment scheitert, die anderen laufen weiter" prüfen will, bekommt mit 401 plötzlich „alle nach dem ersten fehlen". 400 ist ebenfalls untauglich (Prompt-Fallback, #117) — **410 Gone** ist die neutrale TERMINAL-Antwort für solche Tests.
- **Retrofit rejects a Kotlin `Map` parameter, and only at the FIRST REAL CALL (2026-11-20, #184).** Kotlin declares `Map<K, out V>`, so `@PartMap fields: Map<String, RequestBody>` compiles into a signature with `Map<String, ? extends RequestBody>` and Retrofit throws `IllegalArgumentException: Parameter type must not include a type variable or wildcard (parameter #N)` when it builds the service method — i.e. on the first production call, not at compile time and not in any test that mocks the API interface. Two lessons: annotate `@PartMap x: Map<String, @JvmSuppressWildcards RequestBody>`, and remember that a mocked Retrofit interface proves nothing about the wire — the `:analyzer` `ReplayCommandTest` (a real Retrofit client) is what caught this.
- **Whisper repetition-loops on repetitive/musical/noisy/disfluent content — the loop-mask rule survives the shadow's removal (#122 data, now #144's offline analyzer).** On 126 study runs Whisper looped in BOTH the fragment join AND the full-context reference (~1528 vs ~146 tokens on reliable runs). Any join↔full-context diff MUST mask repetition spans on both sides first (compress phrase runs, len 1–8 repeated ≥4×, to one sentinel — analyzer: `/tmp/opencode/seam-run/analyze.py`), or the metric measures the reference's own loops. The 2026-10-14 removal of the online shadow (#143) does NOT remove this hazard: the #144 offline gregor comparison inherits it verbatim.
- **`FragmentTranscriber`'s prompt is ONLY the previous fragment's transcript (#122).** Its length is bounded by ONE fragment (~90 chars/10 s, ~190/21 s, ~550/60 s), so `PROMPT_MAX_CHARS`/`takeLast(800)` **never truncated anything** at the studied fragment sizes and the round-1 premise "800 chars ≈ 30–60 s of prior speech" is false (only the pre-#117 accumulated-context idea would have made it true). Since #124 fragments span `[S, 2S]` (up to 120 s → previous-transcript tails well past 96 chars), the seam-local window DOES bind at the upper end — harmless: the #122 prompt-length sweep (0/96/320/800) showed no effect. Prompt-window length is NOT an accuracy lever.
- **Whisper repetition loops dominate long/hard-content errors — and they propagate through the prompt (#122).** A fragment that loops produces a transcript whose tail is the loop; that tail becomes the next fragment's prompt, so the loop can carry forward. Overlap size, fragment size, and prompt length do NOT stop this (all null in the study). The candidate fix is a loop guard that truncates a repeated n-gram in a fragment's transcript BEFORE it is stored/prompted.
- **`SttRequestRunner.run()` has NO dispatcher of its own — `execute()` runs on the CALLER's context (#117).** Every caller MUST wrap it in `withContext(Dispatchers.IO)`: the fragment transcriber and the batch pipeline do (the #117 shadow comparison initially called it from a Main-dispatched coroutine → `NetworkOnMainThreadException` on the device — shadow removed in #143, the lesson stands). **Robolectric CANNOT catch this class of bug** — mocked `Call.execute()` never touches a socket and main-thread network enforcement is a real-device behavior. Any new caller of the runner gets verified on-device.
- **HTTP 400 on a live-fragment STT request is no longer permanently fatal (#117).** The prompt-carry-over fallback keys on 400: a prompted request that 400s retries ONCE without the prompt and disables prompts for the session. Tests that need a permanent non-transient failure must use another 4xx (401 is the established one) — a 400 with prompt present consumes an extra stubbed response and can flip a failure test green.
- **gregor's hardcoded `vad_filter=True` collapses on long (≥6-min) uploads — fragment sizing and the 5-min cap are CORRECTNESS-critical (#116 Phase 2 data, measured 2026-10-10).** A 16-min recording split into two ≤600-s chunks came back mangled: 588.4 s → **12.8 s after VAD** (2 segments, `no_speech_prob` 0.64, garbled summary text, inconsistent timestamps), 382.9 s → **47.6 s after VAD**, only the final ~61 s transcribed. The live 21-s fragment passes transcribed the SAME audio fully (fragment concat 2310 chars vs full pass 1021 chars — the first ~9 min vanished). Music/action-heavy audio defeats Silero VAD wholesale; Whisper then hallucinates on the remnant. NOTE (#143): the full-context-at-stop strategy this originally guarded is REMOVED, but the #144 OFFLINE analysis (whole-session uploads to gregor) hits the SAME wall — split offline sends to ≤300-s slices, never bulk-upload a long session.
- **Whisper hallucinates on music/credits tails in fragment content too (#116 data, 2026-10-10).** The 16-min movie session's fragment text ended in `"once you go around to the все бесплатно Take off your clothes Hehehehe…"` right after the last real dialogue — the classic Whisper-on-music hallucination, this time INSIDE the live fragment stream (credits music at the recording's end), not only the "Thank you./Thanks for watching." trailing-silence class below. Interesting asymmetry: the full-context shadow pass did NOT produce it (it had already dropped that region). Language detection flails on such chunks (`"nn"`/0.61 on silence, `duration_after_vad: 0.0`).
- `GET /v1/models` is not universally supported. GROQ returns it, some local models (Ollama/LM Studio) may not. Always handle 404 by falling back to free-text model input.
- Retrofit instances for dynamic base URLs must be cached. Creating a new Retrofit instance per call leaks OkHttp connection pools.
- The STT `response_format=verbose_json` returns both `text` and `language` fields in one call — prefer it over separate calls for language detection.
- `PromptStore` must initialize `gson` before `defaults`. Kotlin initializes properties in declaration order. A `loadDefaults()` call that references `gson` after its declaration hits an uninitialized property → NPE → swallowed by catch → fallback defaults used silently.
- `SttProviderConfig` and `LlmProviderConfig` data classes have 5 constructor params with `id` as the only default. In Kotlin 2.1.x, positional args with default params at the front require named args for the rest.
- The `ChatResponse` constructor takes `List<ChatChoice>`, not `List<ChatMessage>`. Each `ChatChoice` wraps a `ChatMessage`.
- OpenRouter's `/v1/models` endpoint is unauthenticated — returns model list for any token (even garbage). The validate flow shows a green checkmark for an invalid token. Always follow model fetch with a minimal chat API call that checks for 401/403 before confirming the token works.
- `ChatRequest` had no `maxTokens` field. The token test call needs `max_tokens=1` to minimize cost. Added as optional `maxTokens: Int? = null` with `@SerializedName("max_tokens")` — existing callers are unaffected since the field defaults to null (omitted from JSON).
- Model save validation must reject empty model text when the model list is non-empty. The check `model.isNotEmpty() && model !in models` short-circuits on empty, allowing blank model names to be saved, silently overwriting valid STT/LLM config.
- Groq retires models without notice — `llama-3.3-70b-versatile` (used by `GroqApiIntegrationTest` via `.env` `GROQ_LLM_MODEL`) is gone (2026-09-11, HTTP 404 `model_not_found`). Symptom: the "LLM cleans up…" test fails at `assertThat(response.isSuccessful).isTrue()`. Replacement logic: `openai/gpt-oss-*` separates reasoning from content and post-processes cleanly (needs generous `max_tokens` — reasoning burns budget); `qwen/qwen3.*` leaks chain-of-thought into the content field; `groq/compound-mini` works but is agentic. `.env` is gitignored — CI unaffected, but local/pre-push test runs break silently on retirement.
- Whisper models (especially v3) hallucinate phrases like "Thank you." or "Thanks for watching." after trailing silence. The default system prompt (#49) instructs the LLM to strip only the trailing hallucination (empty string only if the entire transcription is one) — "Subtitles by Amara" never appears on Whisper. On-device, a **stored** system prompt override keeps the old default until Settings → restore default.
- Model lists must be keyed per endpoint URL, not per section: a globally-stored list survives provider switches and validation then rejects every model valid for the new provider ("red flag on every save, nothing persists"). See `SettingsStore` per-URL cache with 6-week TTL (#50 round 2).
- `getSettledStrings()` callers in `voting_api.tsx` pass only one argument (langId). The function now has a second optional parameter `threshold`. Backward compatible but callers should be updated to pass an explicit threshold.
- The `language_proficiencies` table uses `modelId` as its foreign key field (not `llm_modelsId`). Querying `prisma.language_proficiencies.findMany({ where: { llm_modelsId: ... } })` is a runtime error — the field doesn't exist in the Prisma schema. Use `modelId` and access via `p.modelId` (no `include: { llm_model: true }` needed).
- The `/strings/:sid` "Settlement Score" column in `voting_api.tsx` must sort and display `score` (proficiency-weighted sum), not `voteCount` (raw model count). The `getStringSettlement` return object provides both fields — using `voteCount` for the sort labeled "score" produces incorrect ordering and confuses users.
- F-Droid metadata: when `subdir:` is set, `output:` MUST be removed. fdroidserver's gradle APK auto-detection searches `root_dir/build/outputs/apk/release/` (root_dir = build_dir/subdir), so with `subdir: app` it finds `app/build/outputs/apk/release/*.apk`. Keeping `output: app/build/...` with `subdir: app` globs `app/app/build/...` (double `app`) → "Failed to find any output apks". For a single-module app (gradle root at repo root, module `app/`), the canonical block is `subdir: app` + `gradle: [yes]` + no `output:`.
- **Whisper uploads must never exceed 5 minutes — a hard limit, on BOTH gregor and GROQ (owner, 2026-10-10).** Owner observed that blocks above ~5 min degrade the service: gregor's `vad_filter=True` mangles long uploads and the GPU behaves badly; GROQ has the same practical ceiling. Concretely, the 14-min WAV recording assembled into ~10-min blocks returned 2.3× the fragment join (hallucination; measured against the #117 shadow, removed since #143). Today `WavChunker.MAX_CHUNK_SECONDS = 600.0` (10 min) drives the chunk cap, so the code currently violates this — fix tracked in #120. Any new bulk-upload / assembly path must clamp to 300 s (and not let a byte cap raise it). [ACTIVE until #120]

- **Android 9+ blocks cleartext HTTP by default (#114).** A provider pointing at a plain-HTTP LAN server (`http://10.8.0.16:11437/v1/`) fails validation with `CLEARTEXT communication to <host> not permitted by network security policy`. Fix: permissive `res/xml/network_security_config.xml` (`base-config cleartextTrafficPermitted="true"`) wired via `android:networkSecurityConfig` — deliberate, because users configure arbitrary self-hosted endpoints; do not regress to per-domain exceptions.
- **STT providers disagree on the `language` field format (#105).** GROQ returns the full name (`"German"`), faster-whisper gateways return the ISO 639-1 code (`"de"`) — `capitalizeWords()` on the latter yields `"De"`, not a language name (observed on-device in the clause). Rule: every display use goes through `config/LanguageMapper` (complete Whisper `LANGUAGES` table, codes + names case-insensitive, capitalized-words fallback). Related: GROQ/OpenAI return **no** `language_probability` — only faster-whisper gateways do; `avg_logprob` is transcription confidence, never a language-probability substitute (see DOMAIN.md).
- **Never parallel-upload against the gregor whisper-server — it strictly serializes (#64, measured 2026-10-08).** `hwdsl2/whisper-server:cuda` (`large-v3`, RTX 2070 SUPER, `10.8.0.16:11437`, API token via `sudo docker inspect` on gregor) processes one request at a time: wall time for 4×90 s is constant across C=1..4 (13.1/12.8/12.7/12.8 s), 2×600 s parallel = 53.6 s vs 26.9 s sequential (wall = sum), GPU avg 75–81 % regardless of C. The GPU dips to 0 % between segment batches are per-request pipeline bubbles, NOT concurrency headroom — do not "fix" them with parallelism or treat a <80 % GPU as spare capacity. Parallel requests only queue (per-request latency grows with C). Applies to any future worker/concurrency design → #116 keeps C=1 against serialized providers.
- **STT latency has a per-request floor — naive `duration / x-factor` division misleads (#64 bench).** Measured model `t(S) ≈ a + b·S`: gregor floor a ≈ 0.65–0.9 s (7 s → 0.89 s, NOT 0.24 s), GROQ floor ≈ 0.25 s; slopes b ≈ 0.031–0.045 (gregor) / ~0.005 (GROQ). Content variance is real: two same-length 90-s cuts measured 2.7 s vs 3.8 s — fit robustly (trim/median), never from 3 samples. WAV/PCM is additionally slower than OGG/Opus: decode cost on gregor (180 s: 8.2 vs 6.2 s) and WAN-upload-bound against GROQ (180 s WAV = 5.8 MB → 2.7 s, ~1.8 s upload). Consequence for chunk-size decisions: larger chunks amortize the floor but inflate the stop-tap tail (expected stop→raw ≈ `0.3 + 1.5a + b·S`); smaller fragments below ~7 s buy nothing against the floor.
- **A composed upload is deleted BEFORE the outcome fold — `upload.length()` there reads 0 (#148).** `FragmentTranscriber.process`'s finally-block deletes the composed `upload_%06d.*` (the preparer-owned sources survive) before `result.fold` writes the bundle; any size read after that returns 0. Capture evidence about transient files BEFORE the finally that disposes them.
