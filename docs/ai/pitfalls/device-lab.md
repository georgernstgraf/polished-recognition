# Pitfalls — Devices and the Lab

Moved out of `PITFALLS.md` in #206; entries are verbatim. New pitfalls in this area are appended here.

- **Reproducing IME/layout bugs headless: the emulator AVDs are the cheap evidence (2026-11-13, #157).** `Medium_Phone_API_35` + `Medium_Phone_API_31` exist with the release APK of the working tree. Fast path: `emulator -avd … -no-window -no-audio -no-boot-anim -no-snapshot -gpu swiftshader_indirect -port 5554`; `settings put secure navigation_mode 0` is silently ineffective on Play images — use `cmd overlay enable-exclusive --category com.android.internal.systemui.navbar.threebutton` and verify the nav bar frame (`dumpsys window displays`, 126 px = 48 dp = 3-button, 63 px = gesture handle). **API 31 throws a "System UI isn't responding" ANR right after that overlay switch** — tap "Wait" (or press BACK), it recovers. Then `ime enable`/`ime set`, `pm grant … RECORD_AUDIO`, tap an `EditText` from a `uiautomator dump`'s bounds, `exec-out screencap -p`. Silence the `prepare_*.json`/retention noise by remembering the IME auto-starts a recording when it appears. Watch out: `ime enable` right after `adb install` fails with "Unknown input method" — wait a second and retry.

- **`uiautomator dump` prunes off-screen `ScrollView` children (2026-11-14, #164).** A device audit therefore covers ONE screenful — ≈16 of the ~65 Settings nodes — and the rows below the fold do not appear in the dump at all, so a green run is not a whole-screen proof; scroll and re-run when the missing rows matter. Two companions: a masked field (the API-key `EditText`) is structurally unmeasurable and reports `ink-below-share` rather than a fabricated 1.00:1, and a foreign window in front (a Play-services password prompt) makes the dump describe the wrong screen — the script aborts with exit 2 instead of auditing it.

- **Samsung/Android 13 blocks adbd's recursive mkdir under `/sdcard/Android/data/<pkg>/` (2026-10-11, corpus push to the A03).** `adb push dir/. /sdcard/Android/data/<pkg>/files/samples/` fails with `remote secure_mkdirs failed: Operation not permitted` when the push must CREATE subdirectories (top-level files land fine). `adb shell mkdir`/`cp` CAN write there. Workaround: push to `/data/local/tmp/<dir>` (unrestricted) and `adb shell "cp -a /data/local/tmp/<dir>/. /sdcard/Android/data/<pkg>/files/samples/"`. Related trap: `adb push /path/dir dest/` creates a `dir/` SUBDIR under `dest` — push `dir/.` for contents.
- **`adb install -r` on Oplus re-scans recognition services and perturbs permission state (#82).** Updating the app over adb makes the system re-run `RecognitionServiceInfo.getAvailableServices` (logs "No android.speech meta-data" for every service, incl. Google) and dropped Google's entry from the Voice-Input picker; it also produced a transient `RECORD_AUDIO` denial for our app. When permission/recognition state matters, prefer the normal package-installer path over adb.

- **On-device screen capture for GIFs (#74):** Oplus builds ship **no `screenrecord` binary** (`adb shell screenrecord` → "inaccessible or not found") and `adb` has **no host-side video subcommand** — use `scrcpy --record=file.mp4` from the agent host (server push works over plain adb on Oplus). scrcpy 3.x renamed `--no-display` → **`--no-playback`** (old flag is a hard ERROR). Record with `setsid nohup … &`, stop via `pkill -INT` (finalizes the mp4; note the pkill may hang the shell past timeout — verify death with `pgrep` + file size instead of waiting). GIF recipe (ffmpeg 8): trim to the arc, `fps=10,scale=540:1200,palettegen=max_colors=128` + `paletteuse=dither=bayer` → ~1 MB for ~14 s. Keep the raw mp4 local-only (`/tmp`), commit only the GIF.
- **Google Groups settings pages scroll an inner container (#74)** — Chromium/DevTools "Capture full size screenshot" therefore captures only the viewport height, not the whole settings page (the document height equals the window). Workarounds: the **GoFullPage** extension, or in the DevTools Console list the scroll container (`[...document.querySelectorAll('*')].filter(e => e.scrollHeight > e.clientHeight + 100 && /auto|scroll/.test(getComputedStyle(e).overflowY))`) and take a **node screenshot** of it.
- **`adb pull` cannot read `/sdcard/Android/data/<pkg>/files/` on Oplus (scoped storage) — use `adb shell cat` per file (#117).** Also: `adb shell` inside a `while read` loop EATS the loop's stdin — redirect `< /dev/null` on every adb call inside the loop, and strip `\r` from `adb shell ls` output. Package-name typos (`georgernstgraf/polishedrecognition` vs `georgernstgraf.polishedrecognition`) fail with misleading "No such file or directory".
- **F-Droid testers on headless emulators see no app network traffic** (no API key configured) and may incorrectly conclude "on-device ML claim holds." The app requires a user-configured STT/LLM API key to make any network call. The `INTERNET` permission is legitimate — for user-configured OpenAI-compatible endpoints, not analytics/tracking. When a reviewer questions network traffic, confirm it is emulator system traffic (Google connectivity checks) and clarify the cloud API architecture. (See MR !40029, pando85 test report.)
- **Oplus (OnePlus/OPPO/Realme) ROM blocks adb secure-settings + IME ops from the shell** — `adb shell ime list/enable/set`, `adb shell settings put/delete secure ...`, and `adb shell pm grant ...` all throw `SecurityException: uid 2000 does not have WRITE_SECURE_SETTINGS` (or `GRANT_RUNTIME_PERMISSIONS`). Even `ime list -a` (read) is blocked. Everything (enable IME, set default keyboard, grant mic) must be done via the Settings UI. `dumpsys input_method` / `dumpsys package` (reads) still work and are how you verify IME registration (`mId=.../PolishedVoiceInputIME`, `mShowInInputMethodPicker=true`).
- **`adb install -r` over a signature mismatch fails** with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`. The installed build's signing key must match the new APK. polished-recognition switched from the debug keystore to an RSA-2048 release key (2026-06-28); a phone with an older debug-signed build requires `adb uninstall` first (wipes Groq config) before `adb install`. Same-key reinstalls (`-r`) preserve the config.
- **UI-automation tap coordinates must be scaled to real screen size** — `adb exec-out screencap` PNGs displayed at 900×2000 on this device are actually 1080×2400 (`adb shell wm size`); `input tap` needs REAL pixels (×1.2 from the displayed image). Symptom: taps silently do nothing, focus unchanged. Check `wm size` first, scale from whatever reference image you used.
- **Full voice pipeline runs for real during screenshot sessions** — the device had a configured provider; a stray recording auto-sent and inserted polished text into the focused field. Neutral capture background is mandatory anyway (privacy), but also expect side effects in the host app; cancel dialogs and clean fields after captures.
- **Oplus/OnePlus ROM suppresses app-level `Log.i/Log.w` from the IME service process** — during #60 on-device verification the `VoiceSessionController` "Audio compressed" log never reached logd while framework lines from the same PID appeared fine (13 app lines in buffer, all system-origin). Do not rely on app logcat lines for IME verification on this ROM; use on-screen observation or the rotating /sdcard JSON logs instead. (#60.)
- **`adb shell cmd connectivity airplane-mode enable|disable` works on the Oplus test device** (shell uid; `settings put global airplane_mode_on` alone doesn't apply) — verified 2026-09-01 for the #60 error-path test; `adb shell settings get global airplane_mode_on` returns the state.
- **`adb shell am start` can launch non-exported app activities** (shell holds START_ANY_ACTIVITY) — used for SettingsActivity/VoiceRecognitionActivity driving; the launched overlay appears on the user's screen mid-use, so coordinate with the owner before adb-driving the device.
- **`adb shell ime …` and `adb shell settings put/get secure …` WORK on the S5 (SM-G900F, LineageOS 18.1 userdebug)** — unlike Oplus (previous pitfall), shell holds WRITE_SECURE_SETTINGS there. This enables scripted IME enable/disable, `input_methods_subtype_history` manipulation, and deterministic IME-switch testing on that device. Device dimensions for screenshot taps: S5 = 1080×1920, OnePlus 7T = 1080×2400 — always `wm size` first (#65, clarifies the older 1080×2400-only note).
- **"HeliBoard not installed on the S5" was a misreading** — HeliBoard (`helium314.keyboard/.latin.LatinIME`) IS installed there; it was merely disabled (only enabled IMEs show in `ime list -s`). A disabled keyboard also stays in the subtype history and gets skipped when it's disabled and re-picked when re-enabled. (#65.)
- **Screenshot session on a device with a configured provider: the IME auto-starts recording on field focus** (by design) — a bare `screencap` session therefore contains a live recording with mic status icon; cancel explicitly (× button) after the capture to avoid uploads/insertions; the host app must be neutral (2026-09-07 refresh used Markor on the OPO). (#128 pattern.)
- **On-device demo capture collides with the same phone's chat bridge (#94).** The OnePlus doubles as the Telegram bridge for the agent session, so incoming chat messages appear as heads-up notifications and can overlay a scrcpy recording; `adb input tap` also lands in the wrong app if the intended one is not actually foreground (a `monkey -p …` launch can be silently preempted). Rules: verify the foreground with a throwaway `screencap` before tapping; record long and trim afterward rather than aiming for a precise window; **keep the raw `scrcpy` mp4 until the GIF is signed off** (deleting it forces a lossy GIF→GIF re-encode for any trim change).
- **scrcpy recordings are variable-frame-rate — normalise before measuring (#96).** A `fps=1/4`/`fps=1` contact sheet or a `-ss`/`-t` trim on the raw mp4 drifts by seconds because the input PTS are irregular. Fix: transcode to CFR first (`ffmpeg -i raw.mp4 -vf fps=30 -c:v libx264 -preset veryfast -crf 18 -an norm.mp4`), then derive contact sheets/trims from the normalised file.
- **`adb shell cat` on a missing file still EXITS 0 — the error text lands in the pulled file (#129, 2026-11-12).** `adb exec-out cat <path>` returns exit code 0 and writes `cat: <path>: No such file or directory\n` to the merged stream, so a pull that does not distinguish stdout from stderr stores a 140-byte "session.json" containing that message. 101 of 481 opo bundle dirs were poisoned this way (pre-#142 sessions simply have no `session.json`). Two consequences: `pull` now refuses session dirs without `session.json` (they are not bundles), and `BundleIo.loadAll` skips unparseable bundles with a stderr warning — before that, ONE bad bundle aborted every `scan` of the whole corpus (the #129 natural-find detector). Rule when pulling: check the file's first byte (`{`) or the listing, never trust the exit code.
