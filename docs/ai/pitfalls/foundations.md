# Pitfalls — Foundations and Language Contracts

Moved out of `PITFALLS.md` in #206; entries are verbatim. New pitfalls in this area are appended here.

- **Ein `SharedPreferences`-Getter darf NICHT beim Lesen schreiben — der App-Start-Thread macht ihn zur Rennstrecke (2026-11-24, #200).** `SettingsStoreTest` flakte 2× in ~21 vollen Läufen mit `expected: 0 but was : 2592000`. Die Ursache war **nicht** `QueuedWork` (jede Testmethode bekommt ein eigenes `TempDirectory`, ein verspäteter Disk-Write ist für einen späteren Leser unsichtbar): `PolishedRecognitionApp.onCreate` startet einen MIN_PRIORITY-Thread, der `audioEvidenceStore.evict()` → `retentionSeconds()` → `settingsStore.evidenceRetentionSeconds` liest — und dieser Getter **materialisierte den Debug-Default 2592000** in die Prefs, mitten zwischen `@Before`-`clear()` und Assertion, in der In-Memory-Map derselben Instanz. Regeln: (a) ein Getter ist ein reiner Lesevorgang, nur eine einmalige Legacy-Migration darf persistieren; (b) ein Hintergrund-Thread der App darf Einstellungen lesen, aber nie beim Lesen schreiben; (c) der Startup-Thread heißt `app-startup-maintenance` (`PolishedRecognitionApp.STARTUP_MAINTENANCE_THREAD_NAME`), damit ein Test ihn joinen kann statt zu raten; (d) „Robolectric-Prefs leaken zwischen Testmethoden" war die falsche Diagnose — siehe die korrigierte #142-Lehre weiter unten. Regressionsschutz: `reading the default does not persist it (#200)`.

- **Gson schreibt `null` in ein NICHT-nullbares Kotlin-Feld — die NPE kommt später, außerhalb des `try` (2026-11-20, #187).** Gson alloziert per `Unsafe` und umgeht Konstruktoren; ein `data class Entry(val name: String, val bytes: Long)` hat zur Laufzeit trotzdem `name == null`, wenn der Schlüssel im JSON fehlt (`Long` ist primitiv und wird 0). Der Getter prüft nichts, also fliegt die NPE erst dort, wo jemand den Wert benutzt: im `readManifest`-Fall in `preparedDirFor`s Größenvergleich **nach** dem `catch` — aus „Manifest unbrauchbar, neu bauen" wird ein Absturz. Regel: was die App selbst wieder einliest (Manifeste, Snapshots, Journal-Records), wird über ein DTO mit **nullbaren** Feldern gelesen und **ganz oder gar nicht** validiert (`checkNotNull` im `try`). „Ein Feld ist ja da" ist keine Validierung.
- **`Channel.isClosedForSend`/`isClosedForReceive` sind `@DelicateCoroutinesApi` (2026-11-20, #187).** Die Abfrage ist per Vertrag rennanfällig und wird von kotlinx.coroutines ausdrücklich als Migrationsrisiko markiert; ein `@OptIn` kaschiert das nur. Wenn die Klasse den Kanal selbst schließt (`FragmentTranscriber.cancel()`), gehört der Zustand in ein eigenes `@Volatile`-Flag: gleiche Semantik, keine delicate API. Wasserprobe: ein `drain()` nach `cancel()` muss sofort zurückkehren — schlägt das fehl, hängt der Test, er scheitert nicht (`FragmentTranscriberTest` deckt genau das).

- **The repo's Gson (transitive via retrofit converter-gson 2.9.0) predates `JsonParser.parseString`** (added in Gson 2.8.6) — `JsonParser.parseString(...)` fails to resolve in unit tests. Use `Gson().fromJson(str, JsonObject::class.java)` instead.
- **`VoiceSessionController` has a single primary callback slot — never share it across entry points (#82).** `start{}`/`attach{}` overwrite the slot, `cancel()` nulls it, and orphaned `pendingResult`s deliver only on the next `attach()` (IME re-attaches solely in `onCreate`, so a stolen slot means a deaf keyboard + lost or stale results). A second consumer must observe via `add/removeSecondaryListener` + `startShared()` (live events only, never held results) and must `cancel()` back to IDLE after failures so no PAUSED residue leaks into the IME.

- **Publish externally-visible state only AFTER its backing evidence is written (#117 flake, fixed `f152cd9`).** The pipeline-failure branch set `state = PAUSED` BEFORE `snapshot()` — any observer that saw PAUSED could read missing `session.pcm`/`session.meta` (in tests: the flake's file-race shape; on-device: a process death in that window loses the dictation). The failure branch now snapshots FIRST (`snapshot(force = true)` — the state is still PROCESSING, hence the force) and only then publishes PAUSED. General rule: an externally observable state transition must imply its persisted evidence already exists.
- **Kotlin resolves `ByteArray.lastIndexOf(Byte)` (member) over a same-named extension with a `ByteArray` argument (#116).** Don't name a private helper `lastIndexOf(pattern: ByteArray)` as an extension on `ByteArray` — the member wins the overload resolution and the compile fails confusingly; use a free function name (`lastIndexOfPattern`).

- `runCatching { }` is not a coroutine scope — suspend functions cannot be called inside it. Use `withContext(Dispatchers.IO)` instead.
- `TextInputLayout.error` persists indefinitely until explicitly set to `null`. If no `TextWatcher` clears it on text change, the red error state remains even after the user corrects the input. Always pair `textField.addTextChangedListener { layout.error = null }` when setting `layout.error` from validation logic.
- Kotlin 2.1.x makes `javaClass.classLoader` return type `ClassLoader?` (nullable). Calling `.getResource()` without `?.` produces a compilation warning. Use `javaClass.classLoader?.getResource(…)`.
- `ResponseBody.create(MediaType?, String)` is deprecated in OkHttp 4.12.0, but the replacement extension `String.toResponseBody(MediaType?)` does not exist in this version. Suppress the warning with `@Suppress("DEPRECATION")` rather than using the unavailable extension.
- The global `UncaughtExceptionHandler` in `PolishedRecognitionApp` launches `CrashDialogActivity` in a separate `:crash` process via `Intent.FLAG_ACTIVITY_NEW_TASK`. If the crash occurs on the main thread during Activity lifecycle (e.g. `onCreate`), the intent may not be delivered before the system kills the process. The `:crash` process isolation is a best-effort mitigation — the dialog may not always appear for crashes during early app startup.
- **A silent early-return in a save handler is indistinguishable from a dead button — and the field error may be OFF-SCREEN (#150, fixed `f3cbae0`).** `SettingsActivity.saveAndClose()` validates seven things before it shows its "Saved" toast and closes; the per-app line-wrap width is one of them and sits at the BOTTOM of a long scrolling Settings screen. When it (or any other check) fails, the only feedback was `field.error = …` on a field the user may not be looking at — the report becomes "Save and Back does nothing" and "my config was not persisted", which cannot be triaged. Rule: any validation abort that prevents a user-visible completion MUST also raise a toast (or equivalent) naming what is wrong; log the check key too. Note the ordering trap when analysing such reports: the provider config is written AFTER the provider checks but BEFORE the wrap/fragment checks, so "config empty after restart" proves the abort was EARLY (or the prefs file was lost) — a late abort would have persisted it.
