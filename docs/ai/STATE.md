## #200 — ein Settings-Getter darf nicht schreiben: der Flake hatte einen Thread (2026-11-24, shipped)

- **Was:** `SettingsStoreTest` flakte 2× in ~21 vollen Läufen (`expected: 0 but was : 2592000`, in `evidenceRetentionSeconds defaults to 0` und `legacy audio_evidence toggle migrates OFF to 0`). Die #200-Hypothese — ein verspäteter `SharedPreferences.apply()` aus Test A landet nach dem `@Before`-`clear()` von Test B — war **falsch**.
- **Die Messung, die es entschied:** Robolectric 4.14.1 legt je Testmethode ein neues `TempDirectory` an (`Files.createTempDirectory("robolectric-<pkg>")`) und `ShadowSharedPreferences` ist dort eine **leere** Klasse, es läuft die echte `SharedPreferencesImpl`. Ein verspäteter Disk-Write trifft also eine gelöschte Datei und ist für den nächsten Test unsichtbar; gelesen wird aus der In-Memory-Map, die `clear().commit()` auf derselben Instanz leert. Sichtbar ist nur ein **gleichzeitiger** Schreiber.
- **Der Schreiber:** `PolishedRecognitionApp.onCreate` startet einen MIN_PRIORITY-Thread, der `audioEvidenceStore.evict()` aufruft — und `evict()` liest als Erstes `retentionSeconds()` → `settingsStore.evidenceRetentionSeconds`. Dieser Getter **schrieb beim Lesen**: fehlten Key und Legacy-Toggle, persistierte er `30 days` im Debug-Build, also **2592000** — genau der gemeldete Wert. Landete der Write zwischen `clear()` und Assertion, war der Test rot.
- **Der Fix (Produktion, keine Test-Kosmetik):** der Getter ist jetzt ein **reiner Lesevorgang**. Key vorhanden → clamp+return; **kein** Key und **kein** Legacy-Toggle → `evidenceRetentionDefaultSeconds` zurück, ohne zu schreiben; Legacy-Toggle → einmalige Migration wie bisher. Nebeneffekt (gewollt): ein injizierter Default ≠ 30 Tage wird geehrt statt auf 30 Tage normalisiert. Nutzerverhalten unverändert — die Settings-Seite schreibt beim Speichern explizit.
- **Testseitig:** der Startup-Thread heißt `app-startup-maintenance` (`PolishedRecognitionApp.STARTUP_MAINTENANCE_THREAD_NAME`, Companion `internal`) und `SettingsStoreTest.@Before` joint ihn — ein künftiger Schreiber soll benannt sein, nicht geraten. ## #185 — the recovery UI: the leftovers become visible and actionable (2026-11-21, shipped)

- **Was:** #182 kept the audio, #183 classified the failure, #184 made a retry idempotent — but nothing in the app could SHOW an unfinished dictation, and the only notice was the one-shot IME Toast. The recovery contract existed on disk and had no user surface.
- **Session state in `session.json` (owner idea: a marker in the bundle):** `completedAtMs` (written by `stopAndTranscribe`'s success branch immediately before the existing delete — NOT reordered, #138 is load-bearing), `dismissedAtMs`/`dismissReason`. Unfinished = neither marker. A marker-less session whose records are ALL `DONE` also counts as completed — nothing is left to send, so the honest action is restore. `recoverableSessions()` returns both kinds (newest first) with count/duration/bytes and the failure class of the LOWEST incomplete fragment; a marker-only dir (crash before the first record) is debris and never listed.
- **Dismissal:** `markDismissed` writes the reason FIRST, then deletes every other file — the `session.json` tombstone stays (`no silent drops`). Tombstones are capped by COUNT (`MAX_TOMBSTONES` = 50, newest win) inside `prune` and never consume the 256-MB audio cap.
- **Re-run (`JournalReplay`, `:core`):** replays ONLY the fragments without a stored transcript, splices the stored `DONE` text in index order. Each request is the journal's own composed upload (byte-identical), the RECORDED prompt, `session_id`/`fragment_index` unchanged (the `attempt` counter restarts at 1 — the dedupe identity is the pair); echo trimmed by the newly extracted pure `EchoTrim` (the live worker delegates to it now) against the previous stored transcript, `LoopGuard` on a forced seam, the #117 400-without-prompt fallback. Stops at the FIRST failure (`markFailed` with class + HTTP code); every `DONE` flip is durable, so a cancelled run resumes. `beforeFragment` is a suspend gate.
- **Auto-recovery on Workbench entry (`RecoveryCoordinator`):** scan → banner (GONE at 0) → Toast BEFORE the first request → run. Only `TRANSIENT`/interrupted sessions are retried (`RecoveryReason.autoRetryable`); a dead token, a protocol problem or a rejected request stay for the list. One run at a time, one AUTO attempt per session per PROCESS (`autoAttempted`; no persisted backoff — a restart is a new chance), and the run yields at every fragment boundary while the controller is RECORDING/PROCESSING so the live path keeps the provider.

## #183 — STT failures are classified before anything acts (2026-11-20, shipped)

- **Was:** the runner knew "transient" (5xx/429/IOException) and "everything else". A dead token (five 401s in one session after an endpoint migration) and an unusable 200 were therefore the same category: neither stopped the hammering nor told the user anything they could act on.
- **`SttFailureClassifier` (`:core`, pure):** TRANSIENT (IOException/timeouts, 408, 429, 5xx), AUTH (401/403), PROTOCOL (a 2xx with no transcript, or an undecodable body — Gson/Retrofit validate nothing), TERMINAL (other 4xx, unexpected exceptions). `MalformedJsonException`/`EOFException` are IOExceptions and are matched BEFORE the transient branch.
- **Runner:** AUTH and TERMINAL fail immediately, TRANSIENT retries with `max(backoff, Retry-After)` (10 s per wait, 20 s per request — a longer advice fails instead of retrying early), PROTOCOL repeats the identical request exactly once. `Retry-After` accepts delta-seconds and an HTTP date (`RetryAfter`, injectable clock). The completion log carries `retryAfterMs`; `SttRequestException` carries `failure`.
- **Transcriber:** an AUTH failure sets a session latch — later fragments are recorded as failed WITHOUT a request, and their composed upload still reaches the journal. `resetFailures()`/`cancel()` clear it. PROTOCOL is journaled `NEEDS_MANUAL`; AUTH/TRANSIENT stay PENDING (retryable). "Resume after a token change" needed no new mechanism: the token is read per fragment from `SettingsStore` and `runTranscription` already calls `resetFailures()` — only the latch was missing.
- **Surfacing:** the controller wraps the failure in a `SttRequestException` carrying the class instead of a bare `Exception`; the IME maps AUTH/PROTOCOL through `SttFailureText` to a hint and APPENDS the technical detail. One Toast at stop, no new event, the bar parks PAUSED so Send retries.
- **Redaction:** `LogRedaction` (Bearer, `sk-`/`gsk_`-style keys) runs in `ResponseLoggerInterceptor` before the body reaches `stt-response.json`. The token charset excludes `"`/`'` — a `\S` class ate the JSON's closing quote and produced an invalid log body (found by test).
- **Deliberate deviation:** PROTOCOL repeats the request byte-identically instead of "a conservative shape" as the issue sketched — the only optional field is the prompt, and a prompt problem answers 4xx, not a broken 200. Recorded in DECISIONS.
- **Tests:** 807 → **840** (`SttFailureClassifierTest` 7, `RetryAfterTest` 4, `LogRedactionTest` 4, `SttRequestRunnerTest` +9, `FragmentJournalTest` +2, `FragmentTranscriberTest` +3, `SttFailureTextTest` 4). No version bump.

## #184 — idempotent fragment uploads (2026-11-20, shipped)

- **Was:** every request was a bare multipart WAV with an optional prompt — the third attempt of fragment 7 was indistinguishable from fragment 8, so a lost acknowledgement plus a retry could append the same text twice at a server that does not dedupe.
- **Wire:** `session_id`, `fragment_index` (0-based, the journal/`session.json` key) and `attempt` go out as ordinary multipart fields through ONE `@PartMap` on `transcribeAudioSync`/`transcribeAudio`. An **empty** map omits all three, so the legacy chunk path and every server that ignores unknown fields keep the exact pre-#184 request.
- **Retries:** all attempts repeat the same identity and bump only `attempt`; the #117 prompt-rejection retry (HTTP 400) also re-sends the same identity, or a server would see two fragments.
- **Client guarantee:** `offer()` + the worker already key on the fragment index, and `transcripts.putIfAbsent` is the second line — a second success for one index is dropped with a `duplicate success … dropped` log line instead of doubling the joined text.
- **Pitfall found:** Retrofit rejects Kotlin's `Map<String, out RequestBody>` (`? extends` wildcard) — `@JvmSuppressWildcards` is mandatory, and the failure appears only at the first REAL call; the `:analyzer` `ReplayCommandTest` (real Retrofit) caught it, no mocked test could.
- **Deviation:** no new `session.json` fields — `SessionBundle.sessionId` IS the sent `session_id` and the fragment record is keyed by the same index, so duplicating them would add no verifiable information (DECISIONS entry).
- **Tests:** 802 → **806** (`SttRequestRunnerTest` +3: identity fields, retry identity, empty map; `FragmentTranscriberTest` +1: per-fragment identity). No version bump.

## #182 — durable fragment journal (2026-11-20, shipped)

- **Was:** the fragment audio lived only in `cacheDir/fragments/<sessionId>/` — a cache dir the OS may clear at any time — and the forensic `session.json` (#142) is gated by the retention slider (release default 0). So "the audio is still there" after a failed upload meant "until the next cleanup". The journal closes that gap.
- **Layout:** `filesDir/journal/<sessionId>/` = `session.json` (marker, written first) + `fragment_%04d.json` + `upload_%06d.<ext>`. States `PENDING` → `DONE` | `NEEDS_MANUAL` (the last one is only ever set by #183). Atomic `.tmp` + rename everywhere; the audio is written BEFORE its record, so a crash leaves an orphan file and never a record whose audio is missing.
- **What is journaled:** the **composed upload** (pre-roll + fragment), not the bare fragment — ~1 s pre-roll per fragment (≈2 %), and it makes a retry byte-identical to the original attempt, the property #184's idempotency rests on.
- **Wiring:** `FragmentTranscriber` takes `journal` + `sessionId`; the write-ahead sits in `process()` right after `composeUpload()` and before `sttRunner.run(...)`, the flip after `transcripts[index] = stored`. All journal IO on `Dispatchers.IO` (the worker is Main-dispatched). Best-effort: a journal failure logs and never fails the fragment.
- **Lifecycle:** `VoiceSessionController` creates nothing explicitly (the journal creates its session dir on the first write) and deletes the session inside `discardFragmentSession()` — the single funnel for delivered / cancelled / flushed. The pipeline-**failure** path never reaches it (it parks PAUSED), which is the contract: a failed session keeps its journal until a retry delivers or the user discards it.
- **Cap:** 256 MB over the whole root (`prune`), **no age rule** — an unfinished dictation is never aged away; the newest session and a named live session are never evicted; every eviction logs its reason. Prune runs at app start and after each `deleteSession`.
- **Backup:** `journal/` is excluded in `backup_rules.xml` and in BOTH containers of `data_extraction_rules.xml` (`BackupRulesTest` extended — it pins the exact exclude set and fails on any drift).
- **Deliberate scope cut:** #182 ships **no** unfinished-session scanner (`unfinishedSessions()` is not in the class); cold-start discovery belongs to #185 and is recorded there as its own task.
- **Refactor:** the #132 session-dir clock moved out of `AudioEvidenceStore` into `SessionDirTime` — both stores now order session dirs by the same rule, and `AudioEvidenceStoreTest` stayed green as the regression proof.
- **Tests:** 777 → **802** (`FragmentJournalTest` 13, `SessionDirTimeTest` 4, `FragmentTranscriberTest` +5, `VoiceSessionControllerTest` +2, `BackupRulesTest` +1). No version bump.
- **Not verified:** the force-stop acceptance criterion needs a device (claw has none) — it is an owner check in HANDOFF.md.
